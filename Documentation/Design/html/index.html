ConfigForge 设计说明

面向游戏配置生产流程的命令行工具：把策划表格数据按照 Meta 定义解析、组合、过滤、校验，并导出运行时数据、代码和辅助产物。

当前唯一产品设计入口 面向技术设计 / 用户手册 / QA 自包含 HTML，无外部依赖

1. 总览

ConfigForge 的核心是让 Meta 成为配置数据的结构真相，再从同一份 Meta 和源数据生成多个目标产物。

Meta

结构真相

定义表、字段、类型、默认值、索引、外键、过滤和描述信息。

Source

表格输入

CSV、XLSX、Lark Sheet、Google Sheet 等统一读取成二维 Sheet。

Validation

导出前发现错误

检查 required、type、index、foreign key、asset、text、target mapping 等。

Export

运行时产物

导出 JSON、Lua table、代码、POT、asset manifest 和 manifest。

目标用户

用户关注点
策划 / 内容设计师用表格维护配置，获得清晰错误定位，减少手写数据文件。
客户端 / 服务器工程师定义 Meta、索引和导出目标，得到类型明确的运行时数据和访问代码。
构建 / 发布工程师在 CI 中校验和导出，生成稳定产物、资源清单和国际化模板。
QA基于明确规则设计测试用例，断言过滤、错误提示和产物内容。
工具开发者实现 provider、exporter、validator、code generator 和 plugin 能力。

2. 预期解决的问题

表结构与运行时代码脱节

Meta 描述逻辑结构，工具生成 runtime data 和类型感知代码，避免多处重复维护 schema。

多人协作和版本覆盖

一个逻辑表可以读取多个 sources，并通过 override_sources 做版本、分支或热修覆盖。

发布包数据裁剪

Target/context tag 派生 ExportView，使 shipping、地区、渠道等目标只导出需要的数据。

表内表间一致性

统一检查字段类型、默认值、唯一索引、外键、资源引用和集合级业务规则。

3. 执行阶段图

一次执行从 CLI 与配置解析开始，到产物写入和诊断输出结束。阶段可以内部并行，但对外输出必须稳定。

配置读取与解析数据视图校验/计划产物输出

配置解析

CLI 覆盖 Project 默认配置，解析 target、tag、输出目录和诊断格式。

插件注册

内置能力先注册，插件按配置顺序注册，ID 冲突默认报错。

Meta 与 Source

Meta 支持多文件 import；Source Provider 输出统一二维 Sheet。

DataSet 与 ExportView

先形成完整 DataSet，再按 target/context 派生过滤后的 ExportView。

校验与导出

校验当前视图，通过后规划和生成 artifact，manifest 按路径稳定排序。

并发策略：I/O 任务优先使用异步接口或操作系统 I/O 机制，计算任务使用线程池；可按 source、table、target、artifact 等数据粒度拆分，但所有 diagnostics 和 manifest 必须稳定排序。

4. 配置结构图

Project Config 是入口；Meta 描述数据结构，Target 描述输出方式，Plugin 提供扩展能力。

核心配置片段

[project]
name = "sample"
copyright = "Copyright 2026 Example Studio."

[artifact_writer]
write_mode = "temp_commit"

[[tables]]
name = "items"
kind = "collection"
desc = "所有可获得物品的基础配置。"
source = { provider = "csv", path = "Data/items.csv" }
primary_index = "by_id"

[[targets]]
name = "client_json_shipping"
language = "typescript"
data_format = "json"
tags = ["shipping"]
output = "Generated/Client"
Project 元信息：copyright 可用于生成代码、schema、manifest 等文件头；Artifact Writer 支持 temp_commit 与 direct，推荐正式导出使用 temp_commit。

5. Meta 模型

ObjectTable

导出一个常量对象，常用于全局配置。Override 以 field path 为单位覆盖。

CollectionTable

导出多条记录。可定义 index、primary index，并支持 source order 数组访问。

Polymorphic Fragment

使用 composition 表达多态记录；当前只支持 variant source mode，不支持按 ID 拼接 fragment。

字段关键属性

属性作用说明
desc结构化说明进入 MetaModel，可用于 inspect、代码注释和辅助文档。
required必填规则当前验证视图中无值且无 default 时报错。
default默认值源数据未提供时补齐，且必须能按字段类型解析。
layout复合值书写方式scalar_cell、json_cell、expanded_value。
export / tool_only导出策略控制字段是否进入常规 runtime data。
filter_field过滤引用tool-only 字段被 filter 使用时必须显式开启。
Primary Index：设计取消 primary_key 概念，只保留 primary_index 或 index 上的 primary = true。Primary index 必须是 unique index。
数组下标：expanded_value 中的数组 slot 使用 0-based，例如 rewards[0].item_id；Lua 等 1-based 目标语言差异由 code generator 或 runtime adapter 处理。

6. DataSet 与 ExportView

Full DataSet 保留完整逻辑数据；ExportView 是某个 target/context 实际校验和导出的数据视图。

校验口径：target 相关命令默认校验 ExportView；未指定 target/context 的 validate 默认校验 Full DataSet。

7. 多源与覆盖

Base sources：拆分合并

用于多人协作和内容拆分。CollectionTable 中多个 source 的记录追加成一个逻辑集合；ObjectTable 中多个 source 可提供不同字段。

Override sources：后者覆盖前者

不使用 priority。列表越靠后越晚应用；ObjectTable 按 field path 覆盖，CollectionTable 按 primary index 替换整行。

sources = [
  { provider = "csv", path = "Data/items_base.csv" },
  { provider = "csv", path = "Data/items_event.csv" },
]

override_sources = [
  { provider = "csv", path = "Data/items_hotfix.csv" },
  { provider = "csv", path = "Data/items_shipping.csv" },
]
表格注释与中间数据：Source sheet 允许空行、空列和未映射行/列；没有映射到 field path 的内容不会进入 DataSet，可作为策划注释、公式中间结果或视觉分隔。

8. 导出与 CLI

validate

只校验

读取、组合、过滤和校验，不写正式产物。

config-forge validate --project ConfigForge.toml --target client_json_shipping
export

校验并导出

校验通过后生成 runtime data、代码和特殊产物。

config-forge export --project ConfigForge.toml --target client_json_shipping
inspect

查看合并结果

展示 MetaModel、source resolution、target、desc 和过滤统计。

config-forge inspect table items --project ConfigForge.toml

Runtime Data Format

Format状态说明
json默认易调试，适合通用接入。
lua_table允许Lua 中代码和数据可能合一。
yaml / msgpack / sqlite可扩展由 exporter 支持。
protobuf未来未来需要字段级 field_number，不使用 stable_hash 作为生产策略。

POT 与 text

POT source reference 默认使用 source 表名和行列号；text 可通过额外映射列/行提供 translator comment，也可合并字段 desc。

Artifact Writer

temp_commit 先写临时文件再统一提交，direct 直接写目标路径；两种策略都必须先完成路径冲突检查。

9. QA 输入与断言

QA 测试应优先断言结构化输出和产物内容，而不是只断言人类可读 message。

配置解析

Project/Meta 路径不存在、import 循环、TOML/XML 语法、等价语义。

Source Provider

CSV/XLSX 正常读取、header 缺失/重复、空行空列不进入 DataSet、远程 provider auth_ref。

Field Type

required、default、color channel、vector3、datetime timezone。

Multi-source

base merge、unique 冲突、override 整行替换、后者覆盖前者。

Export Filtering

shipping 过滤、tool-only 字段、过滤后集合级校验。

Desc / 注释

desc 进入 inspect、生成代码注释和 translator comments，多行与特殊字符正确转义。

Artifact Writer

temp_commit 失败不提交最终产物，direct 按配置直接写入，manifest 稳定排序。

推荐断言字段

exit code、diagnostic code、severity、table、field_path、record_key、artifact path、manifest、runtime data 中是否包含/排除指定 record/field。

10. 当前关键设计决策

Meta import

支持多文件，通过 imports/include 引入 TOML 或 XML 定义。

Source provider

csv 和 xlsx 是明确 provider，不再设计 local_file provider。

Override 顺序

override_sources 不定义 priority，按列表顺序应用，后者覆盖前者。

Primary Index

取消 primary_key，仅保留 primary_index 或 primary = true。

Default / Required

缺值时先用 default；required 且无值、无 default 才报错。

Special Exporter

默认读取 ExportView，被 shipping 过滤的数据不进入 POT 和 asset manifest。

Source 注释区

空行、空列和未映射行/列可用于表格注释或中间数据，不进入 DataSet。

并发与写入

I/O 与计算任务分开调度；Artifact Writer 可配置 temp_commit 或 direct。

配置兼容

当前不引入通用 schema version；依赖稳定字符串 name，Protobuf 未来通过显式 field_number 处理兼容。

Builtin

Vector3 等优先作为 builtin；禁止 color_channel = "auto"。

暂不支持

fragment join mode、独立子表式明细布局、模糊 custom runtime format。
