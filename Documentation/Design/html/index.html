ConfigForge 设计说明

面向游戏配置生产流程的命令行工具：把策划表格数据按照 Meta 定义解析、组合、过滤、校验，并导出运行时数据、代码和辅助产物。

阅读摘要，不是 current canonical source 面向技术设计 / 用户手册 / QA 自包含 HTML，无外部依赖

阅读提示

本页是 HTML 阅读摘要，不是 current canonical source。当前产品设计、实现状态矩阵和术语边界以同目录 Markdown 文档为准，尤其是 README.md、01-overview.md、02-execution-pipeline.md 和 06-export-cli.md。当 Markdown canonical docs 与本页不一致时，以 Markdown 为准；维护设计状态或术语时，应同步检查本页是否仍需要更新。

1. 总览

ConfigForge 的核心是让 Meta 成为配置数据的结构真相，再从同一份 Meta 和源数据生成多个目标产物。

Meta

结构真相

定义表、字段、类型、默认值、索引、外键、target tags 过滤和描述信息。

Source

表格输入

当前支持 CSV 和 XLSX（含 sheet 选择、混合来源与公式缓存）；Lark Sheet、Google Sheet 尚未实现。

Validation

导出前发现错误

检查 required、type、index、foreign key、target filtering、validator 和 source schema。

Export

运行时产物

当前支持 JSON、MessagePack runtime data，以及 Rust / TypeScript / C++ 类型代码生成。

目标用户

用户关注点
策划 / 内容设计师用表格维护配置，获得清晰错误定位，减少手写数据文件。
客户端 / 服务器工程师定义 Meta、索引和导出目标，得到类型明确的运行时数据和访问代码。
构建 / 发布工程师在 CI 中校验和导出，生成稳定产物、资源清单和国际化模板。
QA基于明确规则设计测试用例，断言过滤、错误提示和产物内容。
工具开发者实现 provider、artifact generator、validator、data/code artifact toolkit facet 和 plugin 能力。

2. 预期解决的问题

表结构与运行时代码脱节

Meta 描述逻辑结构，工具生成 runtime data 和类型感知代码，避免多处重复维护 schema。

多人协作和多源拆分

一个逻辑表可以读取多个 sources。当前已支持 polymorphic variant source mode、ObjectTable CSV split merge，以及 CollectionTable / ObjectTable CSV override_sources。

发布包数据裁剪

Target tags 通过 export_when 和 row_export 派生 ExportView，使 client/server、shipping/debug、地区、渠道等目标只导出需要的数据。

表内表间一致性

统一检查字段类型、默认值、唯一索引、外键、资源引用和集合级业务规则。

3. 执行阶段图

一次执行从 CLI 与配置解析开始，到产物写入和诊断输出结束。阶段可以内部并行，但对外输出必须稳定。

配置读取与解析数据视图校验/计划产物输出

Project 与 Target

解析 Project Config imports、target tags、data/code task 和输出路径。

Meta Link / Validate

从 Project Config 抽取 MetaModel，构造 LinkedMetaModel 并输出结构化 Meta diagnostics。

Data Load / Resolve

按 DataLoadPlan 加载 CSV，保留 RowSourceInfo，并用 DataResolver 统一解释 default、struct JSON cell / expanded value、fragment presence。

Validation / ExportView

按 target tags、表/字段 export_when、行级 row_export 派生 ExportValidationView 并执行基础规则和 validator registry。

Artifact Generators

生成 JSON / MessagePack / bin runtime data；Rust / TypeScript / C++ code artifact generator 使用逻辑 table name，不绑定真实 data artifact path。

并发策略：当前实现已使用受 jobs 限制的 Rayon CPU worker pool 并行 DataLoader、runtime serialization 和 codegen task；远端 provider、async I/O、完整任务 DAG 和独立 Artifact Writer 仍是后续演进。

4. 当前实现状态矩阵

CSV source providerStableCSV / XLSX 均已实现；远程 Lark Sheet、Google Sheet 是 planned。

DiagnosticsStablesrc/diagnostic/ 已提供 severity、location（含 source column）、entry formatting、report aggregation、code catalog、crate error facade、CLI JSON 输出和 legacy fallback 债务护栏；Project / Build / CLI、Data loading / resolver / validation、Asset resolver、Artifact writer、Generator registry / option / code artifact / data artifact 等高价值错误已迁移为结构化 code/source/location/current/expected/hint。

5. 配置结构图

Project Config 是入口；Meta 描述数据结构和 asset kind，Target 描述输出方式，Plugin 提供扩展能力。

核心配置片段

[project]
name = "sample"
copyright = "Copyright 2026 Example Studio."

[[tables]]
name = "items"
kind = "collection"
desc = "所有可获得物品的基础配置。"
sources = [{ provider = "csv", path = "items.csv" }]
primary_index = "by_id"

[[targets]]
name = "client_shipping"
tags = ["client", "shipping"]

[[targets.exports]]
name = "runtime_json"
type = "json"
output = "Generated/Data/ClientShipping"

[[targets.exports]]
name = "client_ts"
type = "typescript"
output = "Generated/Code/TypeScript"
Project 元信息：copyright 可用于生成代码、schema、manifest 等文件头。Artifact Writer 的 dry_run / direct / temp_commit 已通过共享 ArtifactSink 接入 build 主路径，并执行 artifact path conflict 与 output root containment 检查。

Asset search paths 与 asset kinds

[assets]
case_sensitive = true
require_existing = true

[[assets.search_paths]]
name = "unreal_game"
root = "../UnrealProject/Content"
kind = "filesystem"
mount = "/Game"

[[asset_kinds]]
name = "unreal_asset"
search_paths = ["unreal_game"]
extensions = [".uasset"]
input = "path"
path_style = "mounted_object"
strip_wrappers = ["BlueprintGeneratedClass'{value}'", "Class'{value}'"]
object_separator = "."
object_name = "{stem}_C"
allow_auto_complete = true

[[asset_kinds]]
name = "unreal_skill_class"
extends = "unreal_asset"
base_dirs = ["Skills"]
name_prefixes = ["GA_"]

[[asset_kinds.regex_rules]]
name = "private_engine_escape_hatch"
target = "logical_ref"
pattern = "^/Game/Skills/GA_[A-Za-z0-9_]+\\.GA_[A-Za-z0-9_]+_C$"
message = "技能资源必须是 /Game/Skills/GA_Name.GA_Name_C 格式。"
Asset P0-1 已落地：asset_kind、资源引用校验、导出补齐和 asset_manifest exporter 已接入 runtime build；Asset Manifest 支持 JSON 与 Unreal DataTable CSV 输出。公共 Unreal 等基础规则应放在公共 Meta 片段中，字段专用规则通过 extends 继承；正则规则只作为私有引擎复杂格式兜底，不参与路径重写或自动补齐。

6. Meta 模型

ObjectTable

导出一个常量对象，常用于全局配置。当前实现使用 CSV key,value 行式 source 并输出单 object；支持多 base source split merge 与 override field-path patch；可作为 FK source，但不能作为 FK target。

CollectionTable

导出多条记录。可定义 index、primary index、row_export，并支持 source order 数组访问。

Polymorphic Fragment

使用 composition 表达多态记录；当前只支持 variant source mode，不支持按 ID 拼接 fragment。

字段关键属性

属性作用说明
desc结构化说明进入 MetaModel，可用于代码注释和辅助文档。
required必填规则当前验证视图中无值且无 default 时报错。
default默认值源数据未提供时补齐，且必须能按字段类型解析。
layout复合值书写方式named struct 字段推荐由 source 中 parent path / child paths 自动判定 JSON cell 或 expanded value；显式 layout 主要保留为历史/兼容语义。
export强制导出开关false 表示永不进入 runtime ExportView。
export_whenTarget tags 条件使用 any / all / none 匹配 target tags。
Primary Index：设计取消 primary_key 概念，只保留 primary_index 或 index 上的 primary = true。Primary index 必须是 unique index。

Target Tags 过滤

[[tables]]
name = "skill"
export_when = { any = ["client", "server"] }

[[tables.fields]]
name = "icon"
type = "asset"
export_when = { any = ["client"] }

[[tables.fields]]
name = "damage_formula"
type = "string"
export_when = { any = ["server"] }

Collection 行级过滤

[tables.row_export]
required_tags_field = "export_tags"
excluded_tags_field = "exclude_tags"
match = "any"

# CSV: export_tags 为空表示所有 target；exclude_tags 命中则排除
# id,name,export_tags,exclude_tags
# 1,Potion,,
# 2,Debug Sword,debug,shipping
Field path：第一阶段保留字符为 .、[、]；table field、struct field、fragment name 不允许包含这些字符。数组 / map path 仍是后续扩展。

7. DataSet 与 ExportView

Full DataSet 保留完整逻辑数据；ExportView 是某个 target tags 实际校验和导出的数据视图。

校验口径：target 相关命令默认校验 ExportView；未指定 target 的 validate 默认校验 Full DataSet。

8. 多源与覆盖

Base sources：variant source mode

当前支持 polymorphic CollectionTable 多个 CSV source 追加 records；每个 source 可声明 active fragments，且必须贡献完整 record。

Override sources：CSV

设计上不使用 priority，列表越靠后越晚应用；当前支持 CollectionTable CSV 按 primary index 整行覆盖，并支持 ObjectTable CSV 按 exact field path patch 已存在字段。

sources = [
  { provider = "csv", path = "items_base.csv" },
  { provider = "csv", path = "items_event.csv" },
]

override_sources = [
  { provider = "csv", path = "items_hotfix.csv" },
  { provider = "csv", path = "items_shipping.csv" },
]
表格注释与中间数据：Source sheet 允许空行、空列和未映射行/列；没有映射到 field path 的内容不会进入 DataSet，可作为策划注释、公式中间结果或视觉分隔。

9. 导出与 CLI

dry-run

只校验和规划

读取、组合、过滤、校验并生成 artifact plan，不写正式产物。

config-forge --project ConfigForge.toml --target client_json_shipping --dry-run
build/export

校验并导出

校验通过后生成 runtime data、gettext POT / Lua / Asset Manifest 等聚合或混合产物、schema docs 和目标语言代码；asset_kind 校验和补齐会在导出前执行。

config-forge --project ConfigForge.toml --target client_json_shipping

Runtime Data Format

Format状态说明
json已实现 / 默认易调试，适合通用接入。
messagepack / msgpack已实现二进制 runtime data；生成代码使用逻辑 table name，由 loader / reader 映射真实文件。
bin / binary已实现ConfigForge 私有 positional typed runtime data，带 CFGB header 与 schema revision。
gettext_pot / pot已实现 MVP聚合 data exporter，从可见 text 字段抽取 gettext POT。
lua_table / lua已实现 MVP生成 Lua table 数据与辅助代码，作为 mixed generator 接入。
asset_manifest / assets已实现 MVP聚合可见 asset 引用，支持 deterministic JSON 和 Unreal DataTable 兼容 CSV。
yaml / sqlite未来可扩展通过 build-facing GeneratorRegistry 扩展。
protobuf未来未来需要字段级 field_number，不使用 stable_hash 作为生产策略。

Generated code

Rust / TypeScript / C++ 代码使用 Meta-agnostic RuntimeDataLoader / RuntimeDataReader 契约；用户 loader 不按表生成方法。

Aggregate exporters / Asset resolver

gettext POT、Lua table 与 Asset Manifest 已接入 GeneratorRegistry；asset resolver 已接入 validation 与 runtime export canonical string 输出。

10. Designer Validation Report

Designer Validation Report 是 10-designer-validation-report.md 定义的 P1-1 能力：在不替代现有 CLI diagnostics 的前提下，把结构化校验结果转成更适合策划、QA、制作人和 CI/MR 平台阅读、筛选和归档的报告。当前已实现 MVP。

HTML

人工阅读

面向策划 / QA 的主报告格式，展示顶部阻塞状态、错误摘要、表格行定位、owner/domain 分组和修复建议。

Markdown

MR / CI 摘要

适合贴到 MR comment、CI 日志或变更说明中，包含错误统计、Top tables / codes 和 issue 明细。

JSON

平台消费

保留 stable code、severity、table、field、row、target、owner/domain 和 catalog enrichment，便于平台入库和趋势分析。

CSV

表格工具

导出一行一个 issue 的扁平结构，便于 QA 在 Excel / Sheet 中筛选、分派、统计和留档。

入口与语义

入口示例行为
CLI 参数config-forge --project ConfigForge.toml --target client --report html --report-output out/report/validation.html维持现有 CLI 摘要，同时把完整报告写入指定路径；存在 error 时仍返回失败退出码，但报告应尽量写出。
Build 附加产物[[targets.exports]] type = "validation_report"作为聚合 export task 消费 validation 阶段已有的结构化结果；不重复执行另一套校验逻辑。

报告模型

Metadata

记录 project、target、target tags、生成时间、工具版本和输入根目录，方便 QA 留档与追溯。

Summary

汇总 error / warning 数量、是否阻塞、涉及表数量、owner/domain 覆盖和 Top N 问题分布。

Issues

每条 issue 保留 stable id、severity、code、message、source path、source row、当前值、期望、hint、owner/domain 和 target visibility。

当前状态：已实现 MVP：ValidationReport / DiagnosticReport 可 enrich 成 DesignerValidationReport，并已接入 CLI、HTML/Markdown/JSON/CSV renderer 和 build validation_report export task。后续重点是 owner/domain 映射、current value / expected enrichment 和更多筛选配置。

11. QA 输入与断言

QA 测试应优先断言结构化输出和产物内容，而不是只断言人类可读 message。

配置解析

Project/Meta 路径不存在、import 循环、TOML/XML 语法、等价语义。

Source Provider

CSV 正常读取、header 缺失/重复、ObjectTable key,value、variant source fragments；XLSX sheet、空行列、公式缓存、混合 source 与物理坐标；未实现远程 provider 应显式失败。

Field Type

required、default、color channel、vector3、datetime timezone。

Multi-source

variant source append、fragment presence、跨 source unique 冲突；CollectionTable override 应断言 primary-index 覆盖、missing base row 和 tag-gated 生效。

Export Filtering

target tags、export_when、row_export、export = false 和过滤后集合级校验。

Desc / 注释

desc 进入生成代码注释、translator comments 或辅助文档，多行与特殊字符正确转义。

Asset 引用

asset_kind 缺失、未知 search path、Unreal mounted object path、wrapper stripping、自动补齐唯一性、正则兜底、伪造资源文件存在性。

推荐断言字段

exit code、diagnostic code、severity、table、field_path、record_key、artifact path、asset canonical value、runtime data 中是否包含/排除指定 record/field。

12. 当前关键设计决策

Project imports

Project Config 支持顶层 imports 递归导入配置片段；Meta 文件本身不再声明 imports。

Source provider

csv 和 xlsx 是当前支持的 provider；lark_sheet、google_sheet 是 planned provider，不再设计 local_file。

Override 顺序

override_sources 不定义 priority，按列表顺序应用；当前已支持 CollectionTable CSV 整行覆盖与 ObjectTable CSV field-path patch，后声明的 override 覆盖先声明的结果。

Primary Index

取消 primary_key，仅保留 primary_index 或 primary = true。

Default / Required

缺值时先用 default；required 且无值、无 default 才报错。

Target Tags

Target 使用 tags 描述导出上下文；表、字段、索引用 export_when 匹配，collection 行用 row_export 控制。

Struct source layout

Named struct 使用 JSON cell 还是 expanded value 由 source 中 parent path / child paths 自动判定，不由 Meta field 固定。

废弃旧导出字段

不再保留 tool_only、validator_only、filter_field 作为导出机制；使用 export = false、export_when、row_export 替代。

Asset Resolver

asset_kind 属于 Meta，资源 search_paths 属于 Project；当前已实现校验、runtime export 补齐与 Asset Manifest exporter。

Source 注释区

空行、空列和未映射行/列可用于表格注释或中间数据，不进入 DataSet。

并发与写入

I/O 与计算任务分开调度；当前已有受 jobs 限制的 CPU worker pool，Artifact Writer 可配置策略仍是目标态。

配置兼容

当前不引入通用 schema version；依赖稳定字符串 name，Protobuf 未来通过显式 field_number 处理兼容。

Builtin

Vector3 等优先作为 builtin；禁止 color_channel = "auto"。

暂不支持

fragment join mode、独立子表式明细布局、模糊 custom runtime format。
